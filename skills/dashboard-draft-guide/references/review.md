# Acceptance and quality review

Give reviewers the current user contract and artifact evidence, not a target score to achieve.

| Required condition | Draft evidence | Implementation evidence |
|---|---|---|
| Required information/identity | Source and basic position mapping | Actual rows and required columns |
| Useful pages/metrics | Question, decision, calculation basis | Actual values support the task |
| Main investigation path | Search/select/detail/return plan | Representative actions exercised |
| Time/scope/denominator/missing meaning | Contract and assumptions | Data and calculation reconciliation |
| Useful existing analysis preserved | Retained questions | Same tasks remain possible |

Mark pass/fail/unverified before quality scoring. Missing required information, incorrect mapping, unusable core tasks, or misleading meaning prevent acceptance. Attractive formatting cannot offset them. Unverified required conditions prevent final implementation acceptance.

Preserve a user's existing rubric and weights. Otherwise propose business usefulness, legibility/useful density, investigation/interaction, data meaning, and verified operational response. Proposed weights are not user-approved policy.

Give numeric scores only with supporting evidence, named version/scope, and deductions. Keep design-document judgment, actual render, interactions, and measured performance distinct. A mockup score is not an implementation score. Do not award full performance points without measurement. If no total is supportable, provide findings and an unverified total; a draft can have a clearly provisional score.

```text
Artifact/version and scope:
Draft or implementation:
Required conditions: pass/fail/unverified, evidence
Rubric/weights: existing or proposed
Criterion scores, deductions, evidence:
Blocking defects and concrete next changes:
Unverified rendering/interaction/performance/operations:
Acceptance result:
```

Fix concrete findings and recheck affected work. Retain valid unchanged evidence. Separate publication, schedule configuration, and actual execution from design quality.
