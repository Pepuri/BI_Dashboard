# Request templates

Recover known information before asking the user to fill blanks.

```text
Use $dashboard-draft-guide to design [dashboard].
Audience and decisions/investigations:
Supplied schema, sample, report, profile, or handoff:
Required basic information and interactions:
Freshness/history/performance constraints:
Language, time zone, viewport/accessibility:
Existing analysis to preserve; changed conditions:
Scope: design / local implementation and checks / specified publication.

Recover confirmed decisions and ask only about material unresolved choices.
Explain metric selection, loading, editing method/capability, and acceptance.
Check required tasks before assigning a quality score.
```

```text
Use $dashboard-draft-guide to resume [dashboard].
Current artifact and latest handoff:
Last successful checks and applied/cloud state:
This change:
Preserve agreed requirements and verify affected work.
Leave decisions, evidence, unresolved issues, and next work in the handoff.
```

Keep the user's preferences and project decisions in their own workspace, not this shared package. A profile may define language/time zone, identity fields, density, number formats, key acceptance conditions, and working method. Project-specific scope and schedules belong in the project contract.
